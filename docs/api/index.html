API reference

API version 2026-09-14

The STLabs API lets you read, search, create and update tickets. This reference describes API version 2026-09-14. Versions are handled for you: the command line pins the version it was built for.

Base URL: https://api.stlabs.com/v1

Headers

The command line sends these for you, the idempotency key on writes. If you call the API directly, send them yourself:

HeaderDescription
STLabs-OrganizationThe slug of the organization this request acts on. Every authenticated request must name one.
STLabs-VersionThe API version to answer on. Omit it and the newest published version answers; every response names the version that answered.
Idempotency-Key1-255 visible ASCII characters, chosen by you, so a retry cannot duplicate this. Sending the same key with the same arguments returns the original result for 24h.

Operations

  • POST Add a comment to a ticket /tickets/{ticket}/comments
  • PATCH Change a comment you wrote /tickets/{ticket}/comments/{comment}
  • PATCH Change a queue /queues/{queue}
  • PATCH Change a ticket's fields /tickets/{ticket}
  • POST Change many tickets at once /tickets:bulk_update
  • POST Check who can take a ticket now /people/availability:search
  • POST Count tickets by state, queue or priority /tickets:aggregate
  • POST Create a queue /queues
  • DELETE Delete a comment you wrote /tickets/{ticket}/comments/{comment}
  • POST File a ticket /tickets
  • POST Find queues /queues:search
  • GET Find tickets like this one /tickets/{ticket}/similar
  • GET Get one queue /queues/{queue}
  • GET Get one ticket /tickets/{ticket}
  • GET Get someone's availability /people/{person}/availability
  • POST Link two tickets /tickets/{ticket}/relationships
  • GET List and filter tickets /tickets
  • GET List who works a queue /queues/{queue}/operators
  • POST Make a queue the default /queues/{queue}:set_default
  • POST Move a ticket through its life /tickets/{ticket}:transition
  • GET Read a ticket's conversation /tickets/{ticket}/comments
  • GET Read a ticket's linked tickets /tickets/{ticket}/relationships
  • GET Read the kinds of link between tickets /reference/relationship-types
  • GET Read your organization's priorities /reference/priorities
  • GET Read your organization's queues /reference/queues
  • GET Read your organization's states /reference/states
  • POST Remind the assignee /tickets/{ticket}:nudge
  • PUT Set someone's availability /people/{person}/availability
